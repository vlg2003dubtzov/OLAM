# Модели Rodin → Unity

Unity эту папку не импортирует (имя кончается на `~`).

1. Новый GLB кладётся в `../Incoming/`. Сам файл не переименовываем и не правим: он остаётся исходником.
2. Разбор, только чтение:
   - `python -I glb_report.py <файлы.glb>` — сетки, треугольники, текстуры;
   - `python -I glb_parts.py <файлы.glb>` — отдельные предметы, их размеры и центры.
3. Набор описывается в `SETS` в `rodin_process.py`:
   - центры частей берутся из `glb_parts.py`;
   - `None` — удалить (силуэты человека, шесты);
   - для каждой части задаётся целевое число треугольников и правило реального масштаба.
4. Обработка в Blender (фоновый режим):
   ```
   blender.exe --background --factory-startup --python rodin_process.py -- <Incoming> <staging> <preview> [набор ...]
   ```
   Результат — FBX на каждую часть, текстуры `_BaseColor`, `_Normal`, `_MetallicSmoothness` (R — металл, A — гладкость) и превью GLB.
5. Папку набора из `staging` скопировать в `../Processed/`. Потом в Unity: **OLAM → Rodin → Build Prefabs**, префабы появятся в `../Prefabs/`.

Масштаб у Rodin условный: большая сторона ≈ 1,9. Силуэты человека в моделях ему не соответствуют, поэтому реальные размеры задаются вручную, по источникам.

Очень плотные исходники (миллионы треугольников, как `OLAM_extra6`, 6,5 млн) Blender на этом ноутбуке целиком не берёт: на импорт уходит больше 5 ГБ памяти. Такие файлы обрабатываются по кускам:

1. `glb_split.py` — Python из комплекта Blender, в системном нет numpy. Режет исходник по X на куски `ИМЯ:XMIN:XMAX`. Силуэт просто не попадает ни в один кусок.
2. `rodin_chunk.py` — Blender упрощает каждый кусок отдельным запуском, края разреза не трогает. Пик памяти около 2,7 ГБ на кусок в 2,4 млн tris.
3. `rodin_merge.py` склеивает куски и сваривает края. Получившийся файл подаётся в `rodin_process.py` как обычный исходник.

Так сделан `saxaul_black`. `glb_cluster.py` — запасной грубый способ: он рвёт тонкие ветки, поэтому годится только для черновиков.
